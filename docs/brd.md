## 1. 배경과 문제

관리자 퇴직 시 담당 업무영역과 조직 관계를 근거로 대체 후보를 신속하게 검토해야 하지만, 현재 인사·영역 데이터는 코드, 상태값, 날짜 형식이 일관되지 않아 조인과 비교 결과를 신뢰하기 어렵다. 원천 데이터의 복원 가능성과 계보가 보장되지 않으면 추천 결과의 근거도 감사할 수 없다.

따라서 이번 프로젝트는 통합 레거시 원천을 Bronze에 불변 보존하고 Silver로 표준화하여, 향후 대체인력 추천 시스템이 사용할 수 있는 데이터 기반을 구축한다.

## 4. In scope

- 통합 레거시 원천의 구조와 품질 문제 프로파일링
- Bronze 원문, 원본 행 번호, 계보, SHA-256, manifest 보존
- Silver 표준 컬럼·타입·상태·날짜 변환
- 직원·영역·상위영역·최상위영역 논리 모델과 PK/FK 검증
- RAW_DB 복원율, 원본 무결성, 행 수 대사, Quarantine 정책
- BRD/PRD, 데이터 사전, Medallion 설계, 검증·로그 규칙 작성

## 5. Out of scope

- Gold 계층·추천 피처·`area_manager_features` 설계
- 후보 적합도 가중치, Top-K, 최소점수 확정
- ML 모델 학습·평가·서빙
- 실제 인사발령 자동 결정
- 운영 HA·DR·CI/CD와 사용자 UI 구현

## 6. 업무 규칙과 제약

- `BR-RULE-001`: Bronze 원문은 정정하거나 덮어쓰지 않는다.
- `BR-RULE-002`: 복원율 분모는 Bronze의 고유 `source.record_id`다.
- `BR-RULE-003`: `mgr_act_yn=false`를 승인 없이 퇴직으로 단정하지 않는다.
- `BR-RULE-004`: `REG_DT` 충돌은 기준 원본 결정 전까지 원본별 값을 보존하고 `DATE_CONFLICT`로 기록한다.
- `BR-RULE-005`: 인사정보를 로그와 발표 샘플에 평문으로 노출하지 않는다.
- `BR-RULE-006`: 추천 결과는 향후에도 인사 의사결정 보조이며 자동 발령 근거로 사용하지 않는다.

## 8. 인수 조건

1. RAW_DB 복원율이 95% 이상이다.
2. Bronze 원본 보존 무결성이 100%다.
3. `input = pass + quarantine` 행 수 대사가 일치한다.
4. 승인되지 않은 PK·필수값·FK·도메인·날짜 오류가 0건이다.
5. manifest, 실행 로그, 품질 결과, Quarantine 증적을 재현할 수 있다.
6. Gold 관련 항목은 구현 완료로 보고하지 않고 보류 상태로 명시한다.
