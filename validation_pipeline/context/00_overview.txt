[30초 설명]

이 프로젝트는 MongoDB의 비정형 문서를 추출하고, JSON으로 다룰 수 있게 표준화한 뒤,
품질 검사를 통과한 데이터와 제외된 데이터를 분리 저장하는 공통 파이프라인이다.

처음부터 데이터 구조를 단정하지 않는다.
먼저 공통 변환과 최소 검증을 실행하고, 실제 데이터와 업무 규칙이 확인되면
표준화기 또는 검증기에 필요한 규칙만 추가한다.

[핵심 설계]

- Pipeline은 실행 순서만 관리한다.
- 추출, 표준화, 검증, 저장, 로깅은 서로 분리한다.
- 예상 가능한 데이터 오류는 해당 문서만 제외한다.
- 코드 오류나 시스템 오류는 전체 실행을 실패시킨다.
- 실행 결과는 데이터 파일, 리포트, 역할별 로그로 확인한다.

[읽는 순서]

1. 01_flow.txt       전체 처리 순서
2. 02_modules.txt    코드 파일별 책임
3. 03_logging.txt    로그와 집계 기준
4. 04_changes.txt    실제 규칙을 적용할 위치
5. 05_qna.txt        설명할 때 나올 수 있는 질문
